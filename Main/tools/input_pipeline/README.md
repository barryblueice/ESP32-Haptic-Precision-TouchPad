# 输入链路稳定性与验证

## 实现约定

`main/SYS/report_buffer.c` 是无 RTOS 依赖的报告状态逻辑；`input_pipeline.c` 提供短临界区保护、
采集队列、任务通知、模式请求和统计接口。状态逻辑复用项目已有报告类型，报告布局没有改变。

- 原始队列固定 16 帧；每帧在 I²C 读取前记录代次和时间。采集任务从不等待队列空间。
  队列满或读取失败使当前代次失效，解析任务丢弃旧帧并清理滤波、压力和手势状态。
- 报告缓冲固定 32 项，另有发送任务持有的在途报告。按钮及触点变化按顺序保留；
  相邻且状态相同的移动在入队时合并，边沿报告自身的位置和位移不被后续移动改写。
  已不存在可继续合并的空间时，满队列触发恢复。模拟点击的两个边沿一次性预留容量。
- PTP 移动保留最新绝对坐标；鼠标 X/Y、wheel/pan 使用 32 位累计值，按每轴 ±127 拆分发送。
  合并不刷新最早时间戳，避免持续移动无限延长报告寿命。
- 超过 100 ms 的采集帧、排队报告或尚未提交的报告被取消；恰好 100 ms 仍有效，时间差按无符号处理。
  已提交的传输等待底层完成，不把过期当成重新发送相对位移的理由。
- 恢复增加会话代次，清队列、取消触觉点击、重置手势。连接可发送后先提交全释放报告，
  同时等待输入端观察到无触点、无按钮；恢复前的手势不会补发。
  USB 与 ESP-NOW 等待完成回调确认释放，BLE 以通知成功提交栈为确认边界。
- 模式命令仅由解析任务执行，I²C 超时 100 ms，成功后才更新有效模式。
  正在执行时到达的新请求保留为下一条；失败不自动循环重试，后续相同命令可以重新尝试。
  USB / 2.4G 切换时为旧、新逻辑设备分别发送释放。

USB 事件只由组件创建的 TinyUSB 任务处理。HID 发送任务保留端点忙时的待发报告；异步失败恢复会话。
BLE 连接和 CCC 订阅就绪后发送，拥塞事件控制暂停／恢复；断连不会阻塞输入消费。
BLE 现有两种构建各自仅声明一种输入报告，因此 PTP 构建不把鼠标载荷塞进 PTP 特征。
ESP-NOW 输入和心跳由同一任务串行发送，一次底层发送完成后才复用数据包。

ESP-NOW 沿用现有协议，没有新增接收端应用 ACK；尤其在广播地址下，SDK 发送成功不证明接收端已处理输入。
USB、BLE、无线断连／重新订阅后第一次未完成的手势可能被取消，这是避免卡键和补发旧点击的恢复策略。

## 可重复验证

在 VS Code 配置的 ESP-IDF 终端中运行完整验证：

```powershell
python -B tools/input_pipeline/verify.py
```

也可分别执行：

```powershell
python -B tools/input_pipeline/test_pipeline.py
python -B tools/surface_fw/verify.py --self-test
python -B tools/input_pipeline/check_variants.py
```

输入测试将当前工程的实际 C 缓冲、流水线、USB/BLE/ESP-NOW 发送任务和回调、GPIO 初始化、
旋转函数编译成临时主机动态库。只替换 SDK/RTOS/硬件依赖，并为无限任务循环设置测试步数上限。
测试不复制另一套发送算法；主机桩不模拟双核调度、电气 I²C 故障或真实无线栈。
Windows 使用本机 Clang/lld，不需要主机 CRT；Python 使用 ESP-IDF 环境。
统一验证入口从 EIM 激活配置读取与 VS Code 相同的环境，包含 ROM ELF、OpenOCD 和工具目录。
固件构建使用缓存中的 Xtensa 编译器；主机 DLL 测试自动选择 Windows Clang，避免误用默认嵌入式目标的 esp-clang。
单独运行 Surface 的旧测试入口时，需要确保 PATH 优先找到 Windows Clang；统一验证入口已处理该选择。

新增场景包括：移动累计与拆分、拖动顺序、触点变化、点击成对入队、队列耗尽、过期与时钟回绕、
旧代次确认、采集溢出与读取失败、任务／定时器／GPIO 失败、模式写入失败和执行中到达新命令、
USB GET_REPORT 全长度边界、USB 忙／提交失败／完成失败／拔插、BLE 订阅／拥塞／旧连接事件、
无线串行发送／失败恢复、心跳清零，以及四方向坐标边界。

语法检查复用 `build/compile_commands.json` 中的 ESP-IDF 编译器和选项，通过临时强制包含头覆盖互斥宏，
检查原生鼠标、BLE PTP、独立触觉入口及另外三种旋转；它不修改 sdkconfig、不生成目标文件、不链接另一种固件。
完整固件构建结果只适用于工作区当前默认配置。按用户要求，配置变体不做新的完整构建。

最近结果见 [validation.json](validation.json)，详细日志位于 `build/input_validation/`。
原有 65 项 Surface 检查单独保留；这里的场景数单独统计，避免把语法检查当作硬件测试。

## 板上验收与统计

本轮没有刷写设备、没有实测延迟、无线可靠性、升压输出或触感。
板上验收应分别覆盖 USB、BLE 和 2.4G 的点击／快速连击／拖动／滚动，连接中断和恢复、
按住时切换模式、休眠唤醒、强度 0/25/63/75/100，以及振动故障后的触控使用。

`input_get_stats()` 可读取采集溢出、I²C 失败、提交失败、合并量、报告队列峰值及最长待提交时间。
发送任务每 5 秒最多输出一条发生变化的异常计数日志；不逐帧打印，不写 NVS。
`recoveries` 包括初始化、连接和模式切换引发的恢复，不等同于故障次数。
最长等待值起点在 I²C 读取前，终点为软件最近一次检查待提交报告；不包含主机处理或无线空口延迟。
需要端到端延迟时，应结合板上 GPIO/总线测量和主机输入记录，不能从这些软件计数直接推断。

验收标准是容量内边沿顺序不变、相对移动合并不丢总量、过载后无持续卡键、重连不重放旧点击，
同时现有触觉检查保持通过。性能改善仅在取得实际测量后量化。
