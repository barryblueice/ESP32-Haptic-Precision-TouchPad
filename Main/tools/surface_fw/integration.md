# Surface 振动服务集成与验收

后续输入稳定性改动将手势处理集中到输入任务，并统一了 USB/BLE/2.4G 报告缓冲和故障恢复。
最新输入行为、验证结果及构建记录见 [输入链路说明](../input_pipeline/README.md)。下文的原始集成过程和构建记录作为历史背景保留。

默认运行正常触控板。此前独立五档振动测试由用户报告完成；本次集成固件只完成离线验证和增量构建，尚未刷写设备、尚未进行集成板测。

## 入口与模块

实施时先把已测试的 `main/main.c` 原样复制为 `main/surface_haptic_test.c`，再执行
`git restore --source=f858a7cf24c61f19d712ee2720838c63b0c7e8f4 --worktree -- main/main.c`，
并通过 `git diff` 确认还原内容一致，随后才修改正常入口和振动服务。
复制时原测试文件 SHA-256 为 `966925eeb4aefb88b26825ac9a731d6b210e9b3de5d3d891fb3cefb28ef641f8`；
之后测试文件改为调用共用初始化，因而当前文件哈希不同。

| 模块 | 职责 |
|---|---|
| `main/main.c` | 创建队列、加载 NVS、注册两路 I²C、启动服务及触摸中断，保留连接模式 |
| `main/surface_haptic_test.c` | 可选独立五档测试；与正常入口互斥 |
| `surface_haptic_policy.c` | SAM 强度映射、整对波形配置及 MBOX1 播放 |
| `surface_haptic_runtime.c` | 无硬件依赖的点击快照、8 项队列、取消代次与状态 |
| `cs40l25_surface.c` | 唯一振动任务、心跳检查、休眠唤醒与故障锁定 |
| `surface_haptic_hw.c` | 共用供电、固件和芯片检查、DSP 启动、事件错误锁存和诊断 |
| `surface_haptic_settings.c` | 有效强度、格式校验、NVS 迁移和保存 |

后五个模块位于 `main/I2C/SUB_DEV/`。`CONFIG_SURFACE_HAPTIC_TEST_MODE` 默认关闭。
正常模式先完成触控板 GPIO33 复位，再加载振动固件；振动服务不调用复位脉冲。
MP28167 VREF 和 GPIO14 升压由振动任务管理。SDK 继续执行固件下载、寄存器通信和 ACK；
平台 BSP 的通知回调转交硬件错误，未更换 SDK 驱动或移植原机 BuckBoost 状态机。

## 强度与事件约定

| 强度值 | 按下 | 释放 |
|---|---:|---:|
| 0 | 跳过 | 跳过 |
| 1～38 | 17 | 13 |
| 39～63 | 21 | 15 |
| 64～88 | 24 | 17 |
| 89～100 | 36 | 29 |

默认强度 63。0 仍解析为 `enabled=false, 100/100`，不会写入触发寄存器。
有效反馈采用 `bsp_dut_trigger_haptic(index, 0)`；参数 0 选择 MBOX1 按索引路径，
不表示零毫秒或固定播放时长。CP/GPI 衰减为 0，GPIO 自动触发关闭。
SAM 映射应用于当前 `0x0A0603` 固件；它并不能单独证明触感与原机完全一致。

PTP 压力判定保留滤波、防抖和拖动死区，所有提前返回之后都提交最终按钮状态。
USB／BLE 模拟鼠标在原手势函数完成之后提交最终按钮，包括轻触、右键、中键及双击拖动，
其自动释放也提交一次释放事件；原生鼠标仅观察现有左右按钮的按住／松开状态。
2.4G 保持现有数据包及发送逻辑，本地依据同样的压力／原生按钮状态反馈；本次未新增其原有空白模拟鼠标发送分支。

按下时固定强度和整对波形，释放沿用该快照。非零强度修改只影响下一次点击；
成功设置为 0 会清除未提交事件，当前点击剩余释放静默。
取消的边界为任务提交前最后一次代次检查；已经提交给 BSP 的一次操作可完成，不追加停止波形。
输入侧只有短临界区，不能等待硬件或队列空间。排队超过 100 ms 或队列满时清空积压、
取消点击，若按钮仍按住则等待松开；下一次新的按下才重新接收。
队列事件包含点击编号、波形对、设置值、时间和取消代次。

休眠请求立即取消点击，回调只提交状态请求。任务关闭升压，唤醒时等待至少 250 ms，
必要时恢复并复查 521.6 mV VREF（原始值 652，并非实测 VAMP），检查芯片、DSP 和 78 项波形计数。
按板上 243 kΩ 上拉、10 kΩ 下拉以及 FB 支路串联 1 kΩ 的连接，忽略输入电流及线损补偿时，
该参考值对应标称输出 13.19648 V，约为目标 13.2 V；设置用于正常模式、独立测试及唤醒。
MP28167 的调整只修改 VREF 目标。现有流程仍先使能 EN、等待 250 ms 后才写 VREF；
若芯片采用默认 1 V 参考，上电初期分压目标为 25.3 V，可能触发 23 V 绝对过压保护。
因此 13.2 V 指设置生效后的目标，冷启动和 EN 关断后的唤醒波形仍需核查，不能视为全程电压保证。
唤醒期间旧点击不会补播，也不会重新下载固件。
CS40L25 初始化表及 SDK 构造的 WSEQ 统一保存 `0x3800=0xAA`，对应 Surface SAM
原版的 11000 mV VBST 参数。启动和唤醒完成前回读低 8 位，I²C 失败或不匹配时
交给原有故障流程停止振动并关闭升压。日志包含阶段、目标、回读值及外部升压模式；
故障诊断补充 `0x3800`、`0x3804`、`0x2018`、`0x2014`。
初始化配置表及 WSEQ 写入失败向上传递，失败条目的待更新标记保留，停止后续休眠操作。
保留外部升压模式、`0x3804` 控制选择和现有功放增益；11 V 参数不代表执行器实测 11 V 或 11 Vpp。
原始条目、来源偏移与哈希见 [boost_reference](boost_reference/README.md)。
正常任务约每 10 ms 调度，I²C／ACK 操作仍使用现有同步 BSP；输入上报不等待它们。
最早未确认的活动心跳有固定 2 秒期限，后续点击不延后期限，空闲不要求心跳变化。

初始化、I²C、播放、事件处理、硬件错误或心跳失败时，任务锁定 FAULT、清队列、
输出诊断并关闭升压，结束振动任务；只有重启才重试。触控、HID 和连接任务继续运行。
此隔离针对振动通路故障；如果实际故障拖死触控板与 CS40L25 共用的物理 I²C 总线，
触控通信仍可能受影响，不能用软件任务隔离保证该类电气故障下的触控可用性。

## USB／BLE 与 NVS

强度 Feature Report 为 `0x41`，有效负载恰好一个字节，范围 0～100。
例如 USB HID API 包含报告编号的缓冲为 `[0x41, 63]`；GATT Report 特征的负载仅为 `[63]`。
GET 返回当前有效值。非法强度、空值、额外字节均不能修改当前设置或 NVS。
BLE PTP 及鼠标模式都提供强度特征，应用响应检查长度、偏移和范围，拒绝 prepare／分段写入；
写入失败返回错误，读取从有效设置取值，不使用可被非法写入污染的缓存。
0x42 波形列表和 0x43 手动触发已从描述符、回调、属性与注册表删除。
BLE PTP 注册 7 个报告、鼠标注册 3 个报告（含强度）；清除了未定义属性对应的 PTP Boot 空索引。

新 NVS 键为 `haptic_surface`。新键不存在时，旧 `haptic_click` 的 `0/1/2/3/4`
迁移为 `0/25/63/75/100`，其他旧值或无旧键用 63，写新键并保留旧键。
新键存在时按 0～100 解释，包括值 1～4；越界或错误存储类型修复为 63，不再迁移旧键。
保存失败向上传递错误并保留原运行设置；存储读取错误使用安全默认值，但不盲目覆盖存储。

## 验证与构建记录

执行 `python -B tools/surface_fw/verify.py --self-test --write-report` 可运行所有离线验证并生成报告。
Clang 编译实际策略、事件、设置、振动任务，以及从本项目读取的压力／手势函数体；
RTOS 时间、硬件、NVS 为测试桩。测试覆盖全 256 字节映射及设置输入、参数校验、
错误传播、点击快照、重复帧、拖动、触点变化、溢出、过期、取消代次、休眠唤醒和故障锁定。
HID 检查解析实际短项目，验证 0x41 位宽／范围、集合闭合、旧报告移除及 GATT 属性完整性。
新增 14 个 VBST 场景：使用实际 C 初始化／WSEQ 函数、配置数组、驱动类型及共用硬件流程，
替换总线和时间，验证 11 V 配置、唤醒恢复、回读错误、配置写入失败、WSEQ 条目／终止标记／
休眠命令失败以及诊断寄存器。与已有 51 项一起共 65 项离线检查；不依赖外部逆向目录。

默认正常模式使用 `.vscode/settings.json` 中的 ESP-IDF 6.0 和现有 `build` 增量构建。
没有 clean/fullclean、没有切换构建模式、没有刷写。
BLE PTP 与独立测试分支用 `build/compile_commands.json` 的原编译命令追加宏并执行
`-fsyntax-only` 检查，不修改 sdkconfig，不生成另一种模式的固件。
产物大小、哈希、工具路径和检查结果见 [integration_build.json](integration_build.json)。

## 集成板上验收（待执行）

1. 经用户安排刷写后，冷启动检查固件身份、DEVID/REVID、521.6 mV VREF、启动心跳及 78 项计数，
   检查 `initialize VBST` 日志中的目标为 11000 mV、回读低 8 位为 `0xAA`、外部升压模式为 true。
   测量输出应接近 13.2 V，并捕获 EN 上升至 VREF 设置生效期间的输出波形。
   正常模式应启动所保存的连接模式，不应循环自动振动或播放 ROM/BHM 启动振动。
2. USB 重新插拔使设备重新枚举；若主机仍缓存旧 HID 描述符，删除对应旧设备记录后重连。
   确认 0x41 是一字节 0～100，0x42/0x43 已消失。
3. 先检查 USB 单击、释放、长按拖动、快速连击、抬指、多指取消和接触点切换。
   检查每次逻辑按下／释放只反馈一次；模拟鼠标还检查轻触、双击拖动和右键。
4. 依次设置 0、25、63、75、100，读回并实际点击。0 静默，第四档使用 YM 36/29。
   按住期间从 25 改为 100，当前释放仍用 13，下一次按下用 36；按住期间设为 0 后释放静默。
5. 发送 101、255、空负载、双字节等非法写入，读回值与重启后的值不变；255 不得触发 DFU。
   写合法值后重启，确认 `haptic_surface` 保存有效，迁移不会在每次启动重复执行。
6. 检查原有 BLE／2.4G 模式的移动、点击和拖动，确认包格式未变；BLE 如缓存旧 GATT 表，
   先删除主机配对和对应设备绑定记录，再重新配对。检查强度读写、非法值和分段写入拒绝。
7. 等待配置的空闲休眠，确认 GPIO14 关闭；首次活动恢复升压和 DSP 后，新点击才反馈。
   检查 `wake VBST` 回读低 8 位仍为 `0xAA`，五档按下／释放、ACK 和心跳正常。
   唤醒期间的点击不应稍后突然补播，不能出现重复固件下载。
8. 在受控条件下注入只影响振动通路的 I²C／ACK／DSP 错误，观察诊断、GPIO14 关闭及不再触发。
   确认触控和 HID 上报继续工作；关闭／开启强度或再次唤醒不能解除 FAULT，重启后才重试。
9. 单独记录串口日志、ACK／心跳、实际振动和触感观察；完成上述实际观察后才能标记集成板测通过。
   分别记录“VBST 参数回读通过”和实际电压／执行器波形测量，不以离线测试代替板测。
