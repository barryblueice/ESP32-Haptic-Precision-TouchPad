# 单指关节双敲截屏（实验功能）

## 临时原始数据串口输出

`I2C/TP/tp_raw_trace.h` 中 `TP_RAW_TRACE_ENABLED=1` 临时启用采集，完成后改回 0。
串口沿用当前 UART 控制台设置（115200 baud），采集功能本身不改变识别结果。
原始数据在 I2C 成功读取后、输入队列/坐标滤波/手势识别前复制到独立 128 帧队列，
由低优先级任务输出，采样线程不等待串口打印。内存开销约 10 KB 队列和 4 KB 任务栈。

- `TPRAW`：输入报文元信息；`t` 为采集时刻（ms），`seq` 为有效报文序号，
  `gen/out` 为输入/输出代际，`lost` 为累计串口采集队列丢帧数。控制回复和失败读取不作为有效报文输出。
  当前精简输出不含十六进制 raw 字段，训练导入会结合 TPF 重建触点数据；旧的完整 raw 日志也受支持。
- `TPF`：对应触点的原始 `status、x、y、pressure、major、minor、area`，覆盖接触和抬起帧。
  坐标未经旋转/滤波；`area=major×minor`。抬起帧字节可能是控制器保留值，不应当作接触压力。
- `len=6` 等原生鼠标报文只有 `TPRAW`，没有多点面积数据；采集敲击时应看到 `len=64`。

串口输出时刻可能滞后，以 `t` 比较首帧、压力峰值和双敲间隔。
115200 串口吞吐有限，队列用于缓冲短促敲击；`lost` 增加的片段需重新采集。
建议分别记录普通轻点、指腹双击、单指关节单敲、单指关节双敲，每组做 3–5 次，
每次抬起后等待约 3 秒让日志排空，并标明动作类型。取得数据后再调整联合判定。

目前只实现单指关节双敲截屏，发送 `Win + PrtScn`。不识别双指关节手势，不发送录屏快捷键。
默认启用；参数集中在 `knuckle_gesture.h`，`KNUCKLE_ENABLED = 0` 可完全关闭拦截。

## 可训练识别模型

面积和压力判定已改为从人工标注的原始报文学习，不再逐帧使用固定的面积上限和压力区间。
首帧模型决定是否接管，抬起时通过峰值压力、压力加权面积、时长、首次峰值时间、最大压力上升速度和面积标准差确认整次接触。
分类器、数据导入、重训、数据质量检查及验证说明见 [训练文档](knuckle_training/README.md)。
固件解析器已按用户要求应用 `knuckle_model_v2.h` 的六特征 V2 模型，普通触摸优先。
V1 保留为历史回放基线，训练/比较命令仍不会自动替换模型。

当前训练集含 23 次敲击、28 次普通触摸。训练回放识别敲击 22/23、普通触摸误判 0/28，
5 组新采集双敲各截图一次；仍为实验模型，需要更多独立批次和未参与训练的验收数据。
模型应用未改变用户启用的临时串口日志配置。

## 输入行为和限制

仍只支持单指关节双敲截屏。普通触摸一旦放行，此次触摸不会中途被接管。
首帧模型命中的候选暂存原始报文（最多 16 帧，约 1.3 KB），暂不送入普通解析器。
明显滑动、多指/换指、采样间断、超时或缓冲用满时取消敲击候选，按原顺序补回缓存和当前帧，
后续直接交给原有触摸、边缘及角落手势处理；抬起时分类失败也补回完整接触，恢复普通点击。
每次候选最多观察 120 ms；无新帧时解析任务也会在到期后的轮询中释放缓存（轮询约 10 ms）。
手势和 scan_time 使用原采集时间，补发报告以释放缓存的时间计算传输时效，避免把长按压缩成轻点。
原有报告队列仍可合并同状态的移动报告，落下/抬起边界保留。有效敲击的缓存丢弃，两次有效敲击才截图。
已确认为单次敲击但没有配成双敲时仍不补普通点击；模型重叠导致的静止轻点误判仍需更多训练样本。

接触时长 8–120 ms、连续采样间隔不超过 60 ms、每次最多 64 个接触采样、
原始坐标各轴移动不超过 12；越界当帧交还普通触摸。两敲间隔 60–350 ms（第一次抬起到第二次落下），
落点各轴距离不超过 160。多触点、触点更换、无效坐标/尺寸、长按、滑动和采样中断取消候选。
断连、模式切换和输入恢复丢弃缓存及待配对状态，不跨连接补发旧触摸。手势成功沿用自定义震动开关。

USB PTP、PTP 模拟鼠标和 BLE 模拟鼠标可用；原生鼠标格式没有面积/压力数据，不能识别。
2.4G 接收器需使用更新后的共享 aux_output.c 和 wireless_extension.h 构建，以支持动作 48。
动作 49 不受支持，RSTP 角落动作配置范围保持不变。


## 触摸延迟与诊断

USB 模拟鼠标直接使用合法的旋转坐标，在鼠标轨迹层统一处理跳点与自适应滤波，
不再叠加三点中值延迟。单帧超过 300 坐标单位的突变暂不输出；连续两帧在新位置
30 单位半径内稳定后重新建锚，不发送跳变位移。滤波截止频率 15–120 Hz，
速度滤波 20 Hz、系数 0.04。原生 PTP 保留自身坐标处理，滚动保留原有参数。

压力转发由触摸读取任务在有效帧入队并唤醒解析器后执行，与读取串行，
不创建额外压力任务。每批最多 8 次读取，INT 持续为低时通过 1 ms 单次定时器续读；
长度为 0/2/0xFFFF 的空报告立即结束批次，INT 仍低时 10 ms 重试；真实下降沿仍可提前唤醒。
空读不刷新触摸活动时间。真实读取失败仍退避 10 ms。USB PTP 和鼠标端点均为 1 ms；Windows 选择 PTP 模式时
使用原生 PTP 路径，不会经过模拟鼠标滤波。USB 发送用工作序号保留 pump 运行期间到达的新请求。
PTP 缓存同时记录最新采样时间和最早排队时间，鼠标位移仍累加，触点及按键边界仍保序。
100 ms 超时、溢出、模式切换和故障后的释放/抬手保护保持有效。

`menuconfig → TouchPad Configuration → Aggregate input latency diagnostics every 5 seconds`
对应 `CONFIG_INPUT_LATENCY_DIAGNOSTICS`，默认关闭。开启后低优先级任务每 5 秒输出
`LATENCY` 汇总，不在采集、解析或发送任务中打印，也不持有输入/连接锁打印。
每项含样本数、均值、P95 上界、最大值和固定分桶分布（单位 µs）：

- `capture_interval`：同一输入代次内连续有效按住帧的读取完成间隔，排除抬手后的空闲。
- `read`：I2C 读取耗时；`raw_wait`：读取后进入解析器的等待。
- `parse`：每次解析处理耗时；`force`：每次压力转发调用耗时（含被跳过的调用）。
- `read_to_submit`、`read_to_complete`：读取完成至 USB 接纳/成功完成。
- `usb_flight`：USB 接纳至成功完成；`recover[原因]`：各故障恢复次数。
- `raw_result`：原始读取的空报告、64 字节、其他长度及错误计数；`last_headers` 记录最近有效帧前 4 字节。
- `peaks raw/reports`：原始帧队列与输出队列峰值深度。

读取至 USB 的统计排除合成释放和指关节缓存回放；PTP 合并使用最新样本的诊断起点，
鼠标合并使用最早样本的诊断起点。队列超时检查始终使用最早排队时间，包括 USB 已取出
但尚未提交的报告。诊断日志本身仍有 CPU/串口成本，比较时应保持两次测试的开关一致。

在 Main 目录运行 `python -m unittest discover -s tests -v`，使用 Windows Clang
编译生产 C 代码并注入外设桩。新增回放覆盖滤波、跳点、换指、时间回绕、手势、
缓存合并与恢复、采集/压力事务时序、USB 忙/失败/旧连接完成及唤醒竞态。
编译使用 VS Code ESP-IDF 环境和现有 `build` 目录增量构建，不执行 fullclean。

实机验收：在同一台主机和同一 USB 连接下，对比旧/新固件的起步、慢移、快速反向、
突然停手、压力拖动、双指滚动和指关节截图。正常连续移动 10 分钟应无 `raw_full`、
`raw_age`、`report_age`，无抬手后才恢复的停顿；普通移动 `read_to_submit` 的 P95 目标
不超过 5000 µs。固件内部指标不含控制器采样前等待、操作系统或显示器延迟。
主机回放及构建不能代替以上实机验收。

2026-10-04 USB 原生 PTP 串口对比：此前 INT 持续低时约 570 次读取/秒，
大量无有效帧；对空报告结束批次并退避后，实测空报告均为长度 0。
短时连续按住样本的有效帧间隔均值由 31.67 ms（287 组）降至 13.53 ms（828 组），
最大值由 110.55 ms 降至 15.05 ms。新版读取完成至 USB 提交的各窗口 P95 上界
均不超过 2 ms，839 个提交样本中最大值 13.20 ms；用户反馈已基本顺畅。
这是短时实机验证，尚未完成上述 10 分钟连续移动及完整手势/连接回归。
本次测试开启了汇总诊断；Kconfig 默认仍关闭。数据和固件备份在本地 `build/digiinfo/`。

USB 空闲唤醒：仅当进入 SUSPEND 时输入健康、手指已抬起、主机无按下状态且报告队列为空，
才允许 RESUME 后将唤醒触摸作为新接触继续处理，不要求再次抬手。
原始读取/输出故障、模式或路由切换、USB reset、detach 都会取消该资格；
挂起前已有触点仍走释放与抬手保护。恢复时仍更新输入代次，不回放挂起期间的旧报告。
`tests/test_usb_resume.py` 编译生产输入流水线及报告缓存，回归正常唤醒、重复事件、
PTP/鼠标路径、旧触点、积压、失败/溢出、断连、重置和过期代次。
