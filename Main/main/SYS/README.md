# 单指关节双敲截屏（实验功能）

## 临时原始数据串口输出

`I2C/TP/tp_raw_trace.h` 中 `TP_RAW_TRACE_ENABLED=1` 临时启用采集，完成后改回 0。
串口沿用当前 UART 控制台设置（115200 baud），采集功能本身不改变识别结果。
原始数据在 I2C 成功读取后、输入队列/坐标滤波/手势识别前复制到独立 128 帧队列，
由低优先级任务输出，采样线程不等待串口打印。内存开销约 10 KB 队列和 4 KB 任务栈。

- `TPRAW`：输入报文元信息；`t` 为采集时刻（ms），`seq` 为有效报文序号，
  `gen/out` 为输入/输出代际，`lost` 为累计串口采集队列丢帧数。控制回复和失败读取不作为有效报文输出。
  当前精简输出不含十六进制 raw 字段，训练导入会结合 TPF 重建触点数据；旧的完整 raw 日志也受支持。
- `TPF`：对应触点的原始 `status、x、y、pressure、major、minor、area`，覆盖接触和抬起帧。
  坐标未经旋转/滤波；`area=major×minor`。抬起帧字节可能是控制器保留值，不应当作接触压力。
- `len=6` 等原生鼠标报文只有 `TPRAW`，没有多点面积数据；采集敲击时应看到 `len=64`。

串口输出时刻可能滞后，以 `t` 比较首帧、压力峰值和双敲间隔。
115200 串口吞吐有限，队列用于缓冲短促敲击；`lost` 增加的片段需重新采集。
建议分别记录普通轻点、指腹双击、单指关节单敲、单指关节双敲，每组做 3–5 次，
每次抬起后等待约 3 秒让日志排空，并标明动作类型。取得数据后再调整联合判定。

目前只实现单指关节双敲截屏，发送 `Win + PrtScn`。不识别双指关节手势，不发送录屏快捷键。
默认启用；参数集中在 `knuckle_gesture.h`，`KNUCKLE_ENABLED = 0` 可完全关闭拦截。

## 可训练识别模型

面积和压力判定已改为从人工标注的原始报文学习，不再逐帧使用固定的面积上限和压力区间。
首帧模型决定是否接管，抬起时通过峰值压力与压力加权面积确认整次接触，允许低压力尾帧出现面积突变。
分类器、数据导入、重训、数据质量检查及验证说明见 [训练文档](knuckle_training/README.md)。

当前只有 3 次敲击、2 次轻触，生成的是实验模型。已有采样回放成功不能证明普适性；
仍需更多不同位置、力度、手指和采集批次的正负样本。临时串口日志继续启用。

## 输入行为和限制

仍只支持单指关节双敲截屏。普通触摸一旦放行，此次触摸不会中途被接管。
接管后的候选即使最终分类失败，仍保持隐藏到抬起，不补发点击或拖动。
所以需要同时检验误截图和普通点击被吞掉的情况。

接触时长 8–120 ms、连续采样间隔不超过 60 ms、每次最多 64 个接触采样、
原始坐标各轴移动不超过 60。两敲间隔 60–350 ms（第一次抬起到第二次落下），
落点各轴距离不超过 160。多触点、触点更换、无效坐标/尺寸、长按、滑动和采样中断取消候选。
断连、模式切换和输入恢复清除待配对状态。手势成功沿用自定义震动开关。

USB PTP、PTP 模拟鼠标和 BLE 模拟鼠标可用；原生鼠标格式没有面积/压力数据，不能识别。
2.4G 接收器需使用更新后的共享 aux_output.c 和 wireless_extension.h 构建，以支持动作 48。
动作 49 不受支持，RSTP 角落动作配置范围保持不变。
